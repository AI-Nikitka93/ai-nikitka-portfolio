# DOMAIN ZONE COMPARISON

Проверено: `2026-04-09`

Важно: домен и хостинг — это разные покупки.
- **Домен** = адрес сайта (`kizevich.com`).
- **Хостинг** = где физически лежит сайт и откуда он отдается пользователю.
- Для SEO не нужно покупать дорогой shared hosting, если сайт можно быстро и стабильно отдавать через CDN на кастомном домене.

## Короткий вывод
- **Лучшая основа для бренда:** `.com`
- **Локальная страховка/региональная версия:** `.by`
- **Нормальный запасной вариант:** `.pro`
- **Креативный, но не оптимальный основной домен:** `.me`
- **Не брать при ограниченном бюджете:** `.ai`

## What The Official Docs Actually Mean
- Google Search Central on multi-regional sites: country-code domains are a **clear geotargeting signal**, but they are more restrictive and can only target one country. Google also explicitly says **server location is irrelevant** in that model.
- Yandex Webmaster on choosing hosting: focus on **access speed** and **uptime**, not on buying a specific local host "for ranking".

## Recommendation
- Если нужен **один основной домен** и сайт должен выглядеть серьезно для работодателей, клиентов и глобальных площадок: **берите `.com`**.
- Если бюджет позволяет взять **два домена**, лучшая схема:
  - **Primary:** `.com`
  - **Defensive/local redirect:** `.by`
- Если `.com` вдруг занят или хочется сократить расходы на первый год: **`.pro` лучше, чем `.me`**, потому что он дешевле и ближе к профессиональному образу.

# HOSTING & BUDGET STRATEGY

## Myth To Kill
**Нет, Vercel не делает сайт "хуже для SEO".**

То, что реально влияет:
- кастомный домен;
- скорость;
- стабильность;
- корректная индексация;
- понятный canonical host;
- чистая структура сайта.

По официальным источникам:
- Vercel Hobby is **free forever** and includes a **global, automated CDN**.
- Vercel has official docs for adding a **custom domain**.
- Cloudflare Pages Free supports **custom domains** on the free plan and serves files from a globally distributed network.
- Yandex says to choose hosting by **speed and uptime**.
- Google says not to rely on **IP-based adaptation** and notes **server location is irrelevant** in locale-specific URL geotargeting.

## Practical Budget Strategy

### Option A — Best overall
- **Buy domain:** Namecheap if you buy `.com` / `.pro` / `.me`
- **Host site:** Vercel Hobby
- **Why:** cheapest serious stack, strong speed baseline, easy SSL, easy deploy, good fit if the site later becomes Next.js or Astro
- **Budget:** domain only + `$0` hosting

### Option B — Belarus-first
- **Buy domain:** hoster.by if you need `.by`
- **Host site:** Vercel Hobby or Cloudflare Pages
- **Why:** local ccTLD + free modern hosting
- **Budget:** domain only + `$0` hosting

### Option C — If you insist on CIS/shared hosting
- **Buy domain:** hoster.by
- **Host site:** hoster.by Unix shared hosting
- Verified public page pricing on `2026-04-09` shows list prices around:
  - `Лайт` — `7.9 BYN/mo`
  - `Стандарт` — `20.9 BYN/mo`
  - `Оптима` — `25.9 BYN/mo`
  - `Профи` — `42.9 BYN/mo`
- The same page also exposes a `-25%` promo logic, which maps the Lite plan to roughly `5.93 BYN/mo` for the discounted period.
- **Use this only if:** you need local billing, local panel support, or legal/data reasons.

## Recommended Final Stack

**Primary recommendation:**
- Buy `kizevich.com` on Namecheap
- Host on Vercel Hobby
- Add custom domain
- Set HTTPS
- Set primary host to non-`www`
- If budget allows, also buy `kizevich.by` and 301 redirect it to `.com`

## Why This Is The Best Value
- You avoid paying monthly for hosting before the site even has traffic.
- You keep the SEO benefit of a real domain.
- You keep the technical speed benefits of CDN-based delivery.
- You preserve flexibility if the project later moves to Next.js, Astro, or another stack.

## Important Clarification About Free Subdomains
- `project.vercel.app` or `username.github.io` is not "penalized" just because it is a subdomain.
- But for a **serious personal brand**, it is still the wrong final setup because:
  - weaker memorability;
  - weaker ownership signal;
  - later migration risk;
  - branded queries may split between subdomain and future custom domain.

The weak choice is **staying on the free subdomain**, not **using Vercel with your own domain**.

# BRAND SEO MAPPING (Title, H1, Meta)

Важно: brand SEO не гарантирует `top-1`, но для vital queries это самый реалистичный путь к быстрому доминированию, если:
- домен брендовый;
- главная страница clearly owned by the person;
- все title/H1/meta согласованы;
- Google Search Console и Яндекс.Вебмастер настроены сразу после релиза;
- social profiles and public references point to the same domain.

## What Not To Do
- Не повторять `Никита Кизевич` 4 раза в title.
- Не делать title типа `Никита Кизевич, Кизевич, AI_Nikitka93, Nikitka93, портфолио, блог`.
- Не разносить бренд между разными версиями имени на разных страницах без причины.
- Не использовать разные главные названия типа `AI Nikitka`, `AI_Nikitka93`, `Nikitka AI Studio` одновременно.

## Internal linking rules for vital queries
- В header/footer должен быть один стабильный бренд-анкормаркер: `Никита Кизевич`.
- Со страницы `about`, `portfolio`, `awards-credentials`, `blog` должна быть понятная ссылка на главную.
- На страницах кейсов в intro можно использовать формулу:
  - `Проект Никиты Кизевича (AI_Nikitka93)`
- Не злоупотреблять exact-match anchor на каждой строке. Достаточно естественных повторов.

## Metadata rules based on Google guidance
- Every page gets a **unique, descriptive, concise** title.
- Brand is included **once**, not stuffed.
- Meta descriptions must be **page-specific**, not duplicated.
- Main visible title and `<title>` should not contradict each other.

# INDEXING ACTION PLAN

## Before Release
1. Choose the primary domain and primary host:
   - `https://kizevich.com/`
2. Make sure the site opens in exactly one canonical version:
   - `https://kizevich.com/`
3. Redirect all other versions:
   - `http://kizevich.com/` -> `https://kizevich.com/`
   - `https://www.kizevich.com/` -> `https://kizevich.com/`
   - if bought: `https://kizevich.by/` -> `https://kizevich.com/`
4. Publish:
   - robots.txt
   - sitemap.xml
   - unique titles and meta descriptions
   - valid OG tags

## Google Search Console
1. Open Search Console and create a **Domain property** for the primary domain.
2. Verify ownership via **DNS TXT record**.
3. Submit `sitemap.xml`.
4. Use URL Inspection / recrawl flow for:
   - `/`
   - `/about`
   - `/portfolio`
   - `/awards-credentials`
   - `/blog`
5. Check:
   - Coverage / Page indexing
   - Sitemaps report
   - Performance -> Queries filtered by branded terms

## Yandex Webmaster
1. Add the site in Yandex Webmaster.
2. Verify rights to the site using one of the offered methods.
3. Add `sitemap.xml` either:
   - in `robots.txt`, and/or
   - through the `Sitemap files` section in Yandex Webmaster.
4. Use the `Reindex pages` tool for the main URLs after release.
5. Check:
   - indexing status
   - sitemap processing
   - server response

## Fastest path to branded visibility
1. Release the site on the final custom domain, not on `vercel.app`.
2. Verify in Google Search Console and Yandex Webmaster on the same day.
3. Submit sitemap immediately.
4. Request reindexing for the core pages.
5. Make sure LinkedIn, YouTube, Telegram and any public profiles point to the final domain.
6. Use the same brand string everywhere:
   - `Никита Кизевич`
   - `AI_Nikitka93`

## Monitoring window
- **Day 1:** verification, sitemap submission, request indexing
- **Days 2-7:** check whether homepage and about page are indexed
- **Weeks 2-4:** monitor branded queries in Search Console and Yandex Webmaster

## What To Expect Realistically
- For vital queries, a clean branded domain + exact entity signals usually gives the best shot at fast ranking.
- But **top-1 cannot be guaranteed** in advance.
- What we can control is:
  - strongest brand domain;
  - clean indexing setup;
  - consistent metadata;
  - fast hosting;
  - zero duplicate host confusion.
