## Иллюзия программирования и новая реальность

К 2026 году граница между «программистом» и «оператором ИИ» размылась. Традиционный подход требует лет изучения синтаксиса, алгоритмов и особенностей компиляторов. Однако методология **Prompt-First Workflow** доказывает: глубокое понимание архитектуры систем и способность формулировать логику важнее ручного набора строк кода.

Когда перед вами стоит задача уровня *Senior GPU Engineer* (например, оптимизация CUDA-ядер для новой архитектуры NVIDIA Blackwell B200) или сложная рекомендательная система на Python, а у вас за плечами нет профильного IT-образования, в силу вступает **итеративный цикл промпт-моделирования**.

## Анатомия промпт-петли (Prompting Loop)

Успешное решение сложных алгоритмических задач с помощью ИИ строится не на «одноразовых промптах» (которые обычно приводят к галлюцинациям модели), а на жестком цикле обратной связи:

```
[ Исходный контекст + Спецификация API ] 
                 │
                 ▼
          ┌─────────────┐
          │  Генерация  │◄────────────────────────┐
          │  ИИ-моделью │                         │
          └──────┬──────┘                         │
                 │ (Код)                          │ Лог ошибок /
                 ▼                                │ Метрики
          ┌─────────────┐                         │
          │ Компиляция  │                         │
          │ и Запуск    │─────────────────────────┘
          └──────┬──────┘ (Ошибки / Результаты)
                 │
                 ▼
       [ Рабочее ядро / Код ]
```

1. **Подготовка базы**: Модели (например, *Gemini 3.0 Pro*) передается максимально точная спецификация целевой среды. Это могут быть заголовочные файлы C++, ограничения по памяти GPU, типы данных (такие как `nvfp4` в архитектуре Blackwell) или правила вызова API.
2. **Первичный запуск**: Модель формирует первый прототип решения. Он почти никогда не работает сразу, так как ИИ склонен упускать аппаратные нюансы или совершать мелкие синтаксические ошибки.
3. **Замыкание петли**: Код отправляется в компилятор через CLI. Весь вывод об ошибках, предупреждения и логи выполнения собираются без искажений и отправляются обратно в модель.
4. **Уточнение контекста**: Вместо абстрактного запроса «исправь код», модели передается точечная инструкция: *«Компилятор выдал ошибку X на строке Y при выделении общей памяти Shared Memory. Пересчитай смещение с учетом выравнивания границ 16 байт»*.

## Практический пример: Хакатон NVIDIA Blackwell

В ходе хакатона по оптимизации ядра Dual GEMM для NVIDIA B200, данный цикл был повторен несколько десятков раз. Модель раз за разом перераспределяла регистры и настраивала размерность блоков потоков (thread blocks) на основе логов компилятора CUDA. 

Итог — полностью рабочее ядро с производительностью **56.183 мкс**, написанное человеком, не знающим C++ и CUDA C. Это позволило обойти треть опытных инженеров в мировом лидерборде.

## Главные правила Prompt-First подхода

* **Никакого слепого доверия**: Всегда проверяйте код через реальные компиляторы и тесты производительности.
* **Изолируйте контекст**: Не просите ИИ написать всю систему сразу. Разбейте ее на мелкие изолированные модули (функции, ядра, классы).
* **Скармливайте ИИ документацию**: Если инструмент новый, модель о нем не знает. Скопируйте спецификацию API непосредственно в промпт.
* **Автоматизируйте рутину**: Напишите простые bash/powershell скрипты, которые автоматически запускают тесты и сохраняют логи ошибок для отправки в модель.

Этот подход превращает разработчика из «писателя букв» в системного архитектора и куратора, умеющего правильно направлять вычислительную мощность современных нейросетей.
